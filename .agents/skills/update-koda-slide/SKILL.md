# KODA Slide 업데이트

공식 `koda-slide` 저장소를 `git pull --ff-only`로 업데이트하고 결과를 쉬운 한국어로 안내한다.

## 업데이트 실행

1. 이 `SKILL.md`가 들어 있는 폴더를 `<skill-dir>`로 정한다.
2. `bash <skill-dir>/scripts/update.sh`를 실행한다.
3. 스크립트가 출력한 상태 코드와 메시지를 확인한다.
4. 아래 기준으로 사용자에게 결과를 설명한다.

- `UPDATED`: 이전 버전과 새 버전의 커밋 ID를 포함해 업데이트 완료를 알린다.
- `UP_TO_DATE`: 이미 최신 버전임을 알린다.
- `LOCAL_CHANGES`: 변경 파일 목록을 확인해 보여주고 업데이트를 중단한다. 변경사항을 보관하거나 커밋할지 사용자에게 먼저 묻는다.
- `NOT_GIT_REPOSITORY`: ZIP으로 받은 폴더일 가능성을 설명한다. 공식 저장소를 Git으로 새로 내려받는 방법을 제안하되, 기존 폴더를 삭제하거나 교체하지 않는다.
- `WRONG_BRANCH`, `WRONG_REMOTE`: 안전 검사가 실패했음을 설명하고 자동으로 브랜치나 원격 주소를 바꾸지 않는다.
- `PULL_FAILED`: 네트워크나 권한 오류 등 원문 오류를 짧게 요약하고 재시도 방법을 제안한다.

사용자가 상태만 확인해 달라고 요청하면 `bash <skill-dir>/scripts/update.sh --check`를 실행하고 실제 pull은 수행하지 않는다.

## 안전 규칙

- 로컬 변경사항이 있으면 pull, stash, checkout, reset, clean을 실행하지 않는다.
- 사용자의 명시적 승인 없이 파일을 삭제하거나 로컬 변경사항을 되돌리지 않는다.
- `main` 이외의 브랜치에서는 브랜치를 자동 전환하지 않는다.
- `origin`이 공식 KODA 저장소가 아니면 원격 주소를 자동 변경하지 않는다.
- 일반 merge commit이 생기지 않도록 `--ff-only`를 유지한다.
- Git 명령 자체보다 “업데이트 완료”, “이미 최신”, “작업물 보호를 위해 중단”처럼 사용자가 이해하기 쉬운 결과를 먼저 말한다.

## 사용자 응답 예시

- 업데이트됨: “KODA Slide를 최신 버전으로 업데이트했습니다.”
- 최신 상태: “이미 최신 버전입니다. 별도로 바꿀 내용이 없습니다.”
- 작업물 발견: “수정 중인 파일이 있어 안전을 위해 업데이트를 멈췄습니다. 이 파일을 먼저 보관할까요?”
